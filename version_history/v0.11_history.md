# Feed Parser V0.11 - The Pixel Diff Update

## Changes Made
- Introduced a Python-side "Stage 1" Pixel Difference Gate: Calculates mean absolute pixel difference between current and previous frame, skipping OCR if `diff < 8.0`.
- Increased capture rate in Chrome from 5 FPS (200ms) to 30 FPS (33ms).
- Added Data Quality Filters:
  - Minimum Name Length (blocks names < 3 chars).
  - Background Brightness Sanity Check (blocks bright frames like map UIs, `max_brightness=90`).
  - OCR Text Cleaner (strips leading digits and spaces).
- Upgraded exact-string deduplication to case-insensitive uppercase deduplication.

## Why / Cause
- User wanted 30 FPS for lower event latency, but 30 FPS would crash the OCR engine on CPU. The two-stage pipeline allowed 30 FPS capture while only running OCR on changed frames (~5-10 times/minute).
- Raw data had noise: `JQ`, `13 AAEXADI`, `Gate`, `PARKING`. The new filters act as a rigorous gatekeeper.
- Case-flip duplicates (`SAHUuuuuU` vs `SAHUuuuUU`) bypassed the exact-match deduplication.

## Expected Result
- Event detection latency drops from 200ms to 33ms.
- Partial/gibberish reads and map UI locations are blocked from entering `QL.csv`.
- Case-flip duplicates are blocked.
