# Feed Parser V0.12 - Optimization & Stability

## Changes Planned
- **Move Pixel Diff to Browser**: Shift the pixel difference calculation from Python to JavaScript (`content.js`). The browser will only send an HTTP POST when the frame actually changes.
- **Set Default ROI**: Set default uncalibrated ROI size to exactly `240x24` pixels.
- **Fuzzy Deduplication**: Replace uppercase-exact deduplication with `difflib.SequenceMatcher` (≥ 82% similarity threshold).
- **Time-Based Victim Cooldown**: Lock a victim's normalized name `(T2 + I2)` for 3.5 seconds after a log. Any fuzzy match on that victim within the cooldown is blocked.
- **Trailing Noise Stripper**: Strip characters appearing after a space, or bracket patterns like `[06]`.
- **Soft Dictionary Corrector**: Split OCR text by separators (`-`, `~`, `_`). Fuzzy match against dictionaries. If match confidence is ≥ 85%, auto-correct it. If < 85%, preserve the raw OCR text to ensure new/unknown players are not corrupted.

## Why / Cause
- V0.11 HTTP POST overhead at 30 FPS consumed 90% CPU and 50% RAM because every frame traveled over localhost TCP before being pixel-diffed. Moving the diff to JS stops network traffic entirely for identical frames while keeping local rendering smooth.
- V0.11 Deduplication failed on OCR variations (e.g. `DE~BALDeVGg` vs `DE~BALDeVG9`). Fuzzy dedup solves this.
- The OCR read slightly past the player name into rank badges, pulling in trailing noise (`OV`, `[06]`).
- A 4-second cooldown keyed solely on T2 (victim name) blocked legitimate fast `KNOCK` -> `FINISH` sequences. Keying it on `(T2 + I2)` for 3.5s fixes this.

## Expected Result
- Massive CPU reduction (estimated ~40-50% drop) during active kill feeds.
- Eradication of OCR-variation duplicate logs.
- Cleaner player names in the final CSV.
