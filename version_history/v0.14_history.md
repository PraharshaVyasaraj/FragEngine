# FragEngine V0.14 Version History

## V0.14.0 — Browser-First Event Detection Architecture
* **Shift of Intelligence**: Moved pixel changes and icon detection checks to the client side. The browser determines if an event exists; the backend determines what the event says.
* **Adaptive Sampling Rates**:
  * Normal Mode: Samples every 700ms (Low CPU) when the feed is idle.
  * Rapid Mode: Samples every 200ms when any supported feed icon is present.
* **Transmission Scheduler**: Throttles POST requests during Rapid mode to a maximum of 1 frame per 800ms, sending the latest (clearest) frame.
* **Native GPU Telemetry**: Implemented direct COM/WMI performance counter querying on a separate background thread in Python, capturing Intel UHD iGPU load at <0.1ms query latency.
* **Telemetry Fields**: Exposed EasyOCR average confidence score and computed Levenshtein edit distance on fuzzy auto-corrected player names.

---

## V0.14.1 — Sensitivity Tuning & "Fight Window" Lock
* **"Fight Window" Heuristic**: Once any event triggers Rapid Mode, the engine locks into the 200ms sampling state for a minimum of 15 seconds. New events extend this lock by another 15 seconds, preventing sampling drop-offs during team fights.
* **Sensitivity Calibration**:
  * Lowered `ICON_PIXEL_RATIO` threshold from `0.02` (2%) to `0.005` (0.5%) to catch smaller weapon icons.
  * Lowered `SATURATION_THRESHOLD` from `0.30` to `0.25` for low-contrast frames.
  * Lowered Normal sampling interval to `400ms` (2.5 FPS) to eliminate startup transition lag.
* **Timings Logging Fix**: Modified `parser.py` and `server.py` to preserve and log OCR execution times on unrecognized layouts (which previously incorrectly logged `0ms` to the CSV).
* **Active Ingest Window Summary**: Modified summary calculations in `telemetry.py` to calculate FPS and throughput using the first-to-last request window rather than total server process uptime.

## V0.14.2 — Binarization-First Detection & UI Consistency
* **Binarization-First Density Heuristic**: Replaced color-saturation check in the browser extension with a grayscale binarization density check (threshold `180`). If the white pixel density ratio is between **`3%` and `30%`**, the feed is active. This eliminates false negatives on monochrome white/gray finish icons.
* **Tuned Lock Cooldown**: Set `RAPID_LOCK_DURATION_MS = 1500` (1.5 seconds). This bridges consecutive events under 1.5 seconds, and immediately falls back to Normal Mode (400ms sampling) to conserve CPU during idle periods.
* **UI Contradiction Fix**: If `Feed Present` is `NO`, set `lblNextSend` to `SUSPENDED` in the popup, resolving the confusing `0ms` display state.
* **Telemetry Event Counter Fix**: Refactored `telemetry.py` and `server.py` to classify and track request status (`logged`, `skipped`, `duplicate`). Skipped/unrecognized layout frames are no longer incorrectly counted as logged events.
* **IPC Frame Rate Throttling**: Capped base64 image data previews sent over the Chrome extension message bus to **1Hz** max during idle monitoring, reducing Chrome DOM rendering CPU load.
